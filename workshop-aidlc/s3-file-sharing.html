Portable File-Sharing System

Build a complete web-based file sharing system that runs locally with open-source infrastructure

This workshop references a vision.md file. Download it first before starting.

Workshop Overview

Project: Portable File-Sharing System

Build a web-based file sharing system with MinIO for S3-compatible object storage, ScyllaDB Alternator for metadata, a local API service for gateway-style routing, function-style backend handlers, and React for the frontend. Includes multiple user roles (Admin, Uploader, Reader, Viewer) with role-based permissions.

Portable stack: This workshop teaches the same cloud-native patterns without requiring AWS services. MinIO replaces S3, ScyllaDB Alternator replaces DynamoDB, local API routes replace API Gateway, function-style handlers replace Lambda functions, and Docker Compose replaces CloudFormation/SAM deployment.

Prerequisites

  • Basic React/JavaScript and Python knowledge
  • Access to an AI assistant (Kiro, Claude, Cursor, etc.)
  • Docker Desktop or Docker Engine with Docker Compose
  • Node.js, npm, and Python installed
  • Optional: MinIO Client (mc) for inspecting local buckets
  • Code editor
Workshop 3 Setup Instructions
MinIO
An open-source object storage server compatible with Amazon S3 — stores uploaded files
ScyllaDB Alternator
A DynamoDB-compatible database used here for file metadata and permissions
Docker Compose
Runs MinIO, ScyllaDB, the API, and the frontend together from one config file
RBAC
Role-Based Access Control — granting users different permissions based on their role (Admin, Uploader, Reader, Viewer)
Function-style handlers
Backend logic as small focused functions — each handles one specific operation and could later be adapted to serverless
Named Volume
A Docker volume that persists data between container restarts
Health Check
A periodic test that confirms a container is running correctly
Integration Test
A test that checks multiple parts of the system work together using real services

Task Overview

We have just been hired by a new client who needs a way for their team to share files. They know what frustrates them, not how to build software, so the details are fuzzy. Here is what they have told us so far:

“We want a place where our people can upload files and let others on the team grab them, without emailing huge attachments around. Different people should be able to do different things, some can only look, some can upload, and an admin keeps it all in order. The full details of what we're picturing are written up in the vision.md file.”

For this workshop, the client's full requirements live in vision.md — download it above and skim it before you start. The prompts below read from that file rather than from a description you type in.

Inception AI-DLC 1: Build the User Stories
What's a user story? A user story is a short, plain-language description of something a user wants to do, written from their point of view, usually in the form: "As a Reader, I want to download a file shared with me so that I can use it." Each story also lists acceptance criteria (the specific conditions that must be true for it to count as done). Together, these stories become the contract for everything the AI builds next, so it's worth getting them right.

Construction AI-DLC 4: Build the code for the vision
What are object storage and metadata? Object storage is a place a program puts and fetches whole files — think of it as a giant shared folder a computer can read and write. MinIO provides this on your own machine, standing in for Amazon S3. Metadata is the facts about each file (who uploaded it, when, who it's shared with), kept separately from the file itself; ScyllaDB Alternator is the local database that stores it. Function-style handlers are small backend functions that each do one job, such as "upload a file" or "check a permission." You don't need to write any of this — the prompt tells the AI to wire it up.
