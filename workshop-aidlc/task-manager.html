Task Manager Application

Build a Simple Task Manager - Learn AI-DLC by building something real you can use

Follow the complete AI-DLC methodology to build a local-first task manager with open-source tools.

Workshop Overview

Project: Personal Task Manager | Stack: Python / Flask / SQLite / HTML

Learn the three-phase AI-DLC methodology: Inception (Human-led, AI-expanded), Construction (AI-led, Human-validated), and Operations (AI-assisted, Human-governed).

Prerequisites

  • Basic Python knowledge
  • Access to an AI assistant (Kiro, Claude, Cursor, etc.)
  • Python 3.11+, venv, and pip
  • Browser for the minimal HTML frontend
  • Docker Compose for the Operations packaging step
  • Code editor
Workshop 1 Setup Instructions
Flask
A lightweight Python web framework for building APIs and web apps
SQLite
A file-based database — the entire database is a single .db file; no separate server needed
venv
An isolated Python environment so your project's packages don't conflict with other projects
Docker Compose
Defines and runs multi-container apps from a single docker-compose.yml file
REST API
A way for software to communicate over HTTP using standard methods (GET, POST, DELETE)
User Story
A short feature description from the user's point of view, e.g. "As a user, I want to add a task"
Acceptance Criteria
Specific conditions a feature must meet to be considered complete
Component Model
A design blueprint describing the building blocks of a system and how they interact

Task Overview

We have just been hired by our new clients to create a hit new app. However, they are very vague as to what the app is and what they want. Here is what they have told us so far:

“We want a simple task manager such that a user can add tasks to do for the day. Users should be able to view them all at once, and be able to give them labels of importance based on how important that specific task is. There should be a feature to delete tasks from the current list as well. These are all the features that we need at this time.”

Tips

  • Answer questions in the files, not in chat. Open the markdown file, fill in your [Answer]: tags, then tell the AI to re-read.
  • Context resets are optional but valuable for long sessions. If the AI starts losing track of earlier decisions or output quality drops, start a fresh chat and resume from aidlc-state.md. For short workshops, you can often skip this.
  • Don't edit generated code directly. If something's wrong, tell the AI to update the design first, then regenerate.
  • You're always in control. Nothing proceeds without your approval. Say "Request Changes" anytime.
  • Check aidlc-state.md to see where you are at any point.
